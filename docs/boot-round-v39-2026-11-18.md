把 v39 内核刷进真机，并第一次在实机上验证了 v39 的元类修复**。同时记录所有踩过的坑和当前卡点，
供后来者复现与接手。

v39 的实机证据（照片 IMG 记录）：

```
NativeUfs: M:reg pre p=0xfffffff007adb6b0 link=0xfffffff007add1d0
NativeUfs: M:reg pre fixed link=0xfffffff007add1d0
U:meta-ok
M:stalled post h=... cnt=1 c0=0xfffffff007adb7e0 c1=0
M:stalled scan ok ... cnt=0 c0=0x1 c1=0x6
```

- `link=` 是家族元类 `IOBlockStorageDevice::gMetaClass`，**不是** v38 的毒值 `0x3135205b0a293061`；
- `meta-ok` = ABI 闸 + 有界链校验通过；
- `M:stalled post cnt=1` 且 `scan ok` = 本类这次正常进入登记批次，没有被护栏丢掉。

## 与 v38 的差异（必须知道）

为了让 Linux 构建链跑通，这一轮的内核**关掉了一批依赖作者本机归档/闭包的功能**，与 v38 不等价：

```
CONFIG_XNU_BUILD_ARCHIVES=y          # 必须开，否则 archives 一个都不跑
CONFIG_XNU_BOOT_PROGRESS=n           # 该分支没有 build-boot-progress.py
CONFIG_XNU_NATIVE_UFS_VERIFIED=n     # VerifiedRoot 闭包未移植到 Linux
CONFIG_XNU_VERIFIED_ROOT_PROBE=n
CONFIG_XNU_OWNER_ROOT_AUDIT=n        # 连带 ROOT_TRUST / DATA / CACHE / UNION / BOOT_MANIFEST
CONFIG_XNU_NATIVE_AES=n              # 依赖原始 AES 闭包
CONFIG_XNU_NATIVE_RAM_BLOCK=n        # 仅 owner data mount 需要
CONFIG_XNU_NATIVE_VIRTIO_BLOCK=n     # liuqin 不走 virtio
CONFIG_XNU_NATIVE_ADRENO=n           # GPU 归档缺
CONFIG_XNU_NATIVE_LEGACY_DISPLAY=n   # 显示归档缺
```

面板里程碑（`K/B/U/M`）由 `liuqin_fb_putc()` 直接写 framebuffer，不依赖上述任何一项。

## 实机启动时间线（干净参数下）

```
K49:PE_init_iokit
K50…K58:PE_lockdown_iokit
B68…B96:bsd_init … at_callout / at_callout_done
M:stalled pre → post → scan ok      （本类登记成功）
U:59:probe-expert_init
U:60:start-root
U:61:r0-enter        ← v39 prologue 开始
U62:r1-base          ← 拿到 IOBlockStorageDevice 元类
U64:r2-abi           ← ABI 闸通过
NativeUfs: M:reg pre/fixed
U65:r3-adopt
U66:meta-ok
U67:r4-host          ← 进入 hostBringUp
U68:h:controller map
U69:h:DMA allocation
U70:h:lock / U71:h:lock-ok
U72:h:alloc          ← 卡在这里：IOBufferMemoryDescriptor 物理连续分配
```

## 当前卡点：`hostBringUp` 的 DMA 分配

`hostBringUp()` 里第一次分配：

```cpp
IOBufferMemoryDescriptor::inTaskWithOptions (kernel_task,
    kIODirectionInOut | kIOMemoryPhysicallyContiguous | kIOMemoryMapperNone,
    kDmaBytes /* ~1 MiB */, 4096);
```

调用不返回（不是失败，是挂住）。这一路径在 v38 里从未被执行（v38 在 gate 就返回了），
属于首次走通的代码。已尝试：先在循环里改从最小区域（1 槽）开始，并给每种尺寸单独打点，
下一轮实机可直接看出是"1 槽也挂"还是"只有 1 MiB 挂"。

## 下一轮建议（按优先级）

1. 用最小 DMA 尺寸先过 `hostBringUp`（若仍挂，改 `IOMallocContiguous` 或分块描述符）；
2. 过了之后依次看 `h:stopq`、`h:SMMU and request list`、根窗口发布里程碑；
3. 根窗口发布成功后再讨论 `build userdata`（**会清空 Android 数据**，务必先备份）；
4. 用户态（launchd / 显示 / 触控）放到最后，参考同类机型的节奏是周–月级。

## 本轮构建链问题总表

| # | 现象 | 根因 | 处理 |
|---|---|---|---|
| 1 | `can't open file scripts/build-boot-progress.py` | 该分支缺此脚本（新树已改为纯补丁实现） | `CONFIG_XNU_BOOT_PROGRESS=n` |
| 2 | `defconfig line N: value must be y, n…` | 解析器不接受行尾注释 | 注释独立成行 |
| 3 | `line 745: test -f "$CRYPTO_ARCHIVE" failed` | `CONFIG_XNU_BUILD_ARCHIVES` 未开，archives 未构建 | defconfig 加 `=y` |
| 4 | `ModuleNotFoundError: native_prelink` | 设备脚本找 `kits/XnuPrelink`，旧树叫 `kits/NativePrelink` | 脚本改为按内容探测；补 `scripts/kernel_target.py` |
| 5 | `No reference candidate available` | AMFI/PMGR 审计需要 `build/xnu-prelink/*candidate.macho`（作者本机产物） | 回退到 `out/ipsw/<build>/kernelcache.decompressed`（真校验，非绕过） |
| 6 | `llvm-objcopy: option is not supported for MachO` | `--globalize-symbol` 不支持 Mach-O | 用 Python 直接改 nlist 的 `n_type |= N_EXT` 一字节 |
| 7 | `xcrun: dwarfdump: not found` | Linux 工具链无 dwarfdump | `/opt/unixnu-linux/bin/dwarfdump` 垫片到 `llvm-dwarfdump` |
| 8 | `clang: no such file drivers/NativeUfs/NativeUfs.cpp` | 脚本写死目录名 | 映射 `NativeUfs → drivers/ShengUfs`，归档名 `libShengUfs.a`、`libRamBlock.a` |
| 9 | `NativeRamBlock requires the qualified original storage/AES prelink closure` | 关掉 AES 后守卫触发 | 同时 `NATIVE_RAM_BLOCK=n`（owner data mount 已关） |
| 10 | `rootUnauthGateOpen` unused → `-Werror` | 该函数只在未验证分支被调用 | 用同样的 `#if` 包住定义 |
| 11 | 链接缺 `armcpu_spi_mask` / 多余 `arm64_platform_sleep_hook` | 树里 ArmCpu 版本与内核期望不匹配 | 钉 `a823383`（有 SPI mask、无 sleep hook） |
| 12 | `patch does not apply osfmk/arm64/start.s:697` | 第二次构建在已打补丁的树上重打 | 预打一次补丁 + 设 `UNIXNU_PATCH_LIST` 让脚本跳过自己的循环 |
| 13 | `The owner boot manifest needs XNU_OWNER_ROOT_VOLUME_UUID` | 新树要求 OS profile 的 root 卷 UUID | `board.toml` 加 `[root] os_volume_uuid`（占位） |
| 14 | `payload: native UFS root boot needs exactly one sheng-pmgr=2` | 新树校验新参数名 | 参数里同时保留 `pmgr=2` 与 `sheng-pmgr=2` |
| 15 | `boot image header does not match the requested parameters` | 校验器按 v0 偏移解析 v4（误报） | 忽略；镜像本身正确（`header_size=1584`、ramdisk=68157440） |
| 16 | UniXNU 菜单 `no boot entry found` / `fs=0` | **`LIUQIN_INITRD_DISK_ENABLED` 未定义**，`UniXNURamDiskDxe` 从未被打进 FV | `liuqin.dsc` 里 `DEFINE LIUQIN_INITRD_DISK_ENABLED = 1` |
